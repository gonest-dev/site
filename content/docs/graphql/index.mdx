`GraphqlResolver` is analogous to `Controller` — registered via `module.Resolvers(...)`, reusing the exact same `Schema`/`Parse[T]`/`MustInject` as REST. Zero duplication of validation logic or DI setup between REST and GraphQL.

By convention in GoNest projects, resolver reference variables end with a trailing underscore (`_`), e.g., `UserResolver_`.

```go
package user

import "github.com/gonest/gonest"

var UserResolver_ = gonest.NewGraphqlResolver(func(resolver *gonest.GraphqlResolver) {
	userService := gonest.MustInject[UserService](resolver)

	resolver.Query("user", func(query *gonest.GraphqlQuery) {
		query.Args(userIdParamsSchema)   // exact same Schema used in REST validation
		query.Returns(userEntitySchema)  // exact same Schema feeds generated SDL

		query.Handler(func(ctx *gonest.GraphqlContext) any {
			args := gonest.MustParse[UserIdParams](ctx.Args(), userIdParamsSchema)
			return userService.Get(args.UserId) // returned value IS the data
		})
	})
})
```

<Callout type="info">
  The `owner` for `MustInject` must be `resolver` itself (or another Resolver/Controller) — the `Query`/`Mutation`/`Subscription` builders passed into their callbacks do not have independent DI capabilities.
</Callout>

## Registering Resolvers in a Module

To register resolvers inside a GoNest module, pass them to `m.Resolvers(...)`:

```go
package user

import "github.com/gonest/gonest"

var UserModule_ = gonest.NewModule(func(m *gonest.Module) {
	m.Name("UserModule")
	m.Providers(
		UserServiceProvider_,
	)
	m.Resolvers(
		UserResolver_,
	)
})
```

## Query and Mutation

Both share the exact same signature shape — `.Args(schema)`, `.Returns(schema)`, `.Handler(func(ctx *gonest.GraphqlContext) any)`. The value returned by the Handler becomes the `data` payload of the GraphQL response, matching NestJS behavior:

```go
resolver.Mutation("createUser", func(mutation *gonest.GraphqlMutation) {
	mutation.Args(userEntitySchema)
	mutation.Returns(userEntitySchema)

	mutation.Handler(func(ctx *gonest.GraphqlContext) any {
		input := gonest.MustParse[UserEntity](ctx.Args(), userEntitySchema)
		userService := gonest.MustInject[UserService](resolver)
		return userService.Create(input)
	})
})
```

`gonest.GraphqlMutation` is a type alias for `gonest.GraphqlQuery` — the root GraphQL type assigned in generated SDL (`Query` vs `Mutation`) is determined by the method that registered it.

Both dispatch via a single fixed HTTP endpoint, `POST /graphql`, following standard GraphQL-over-HTTP (`{query, variables, operationName}` → `{data, errors}`).

## Subscription

Fundamentally different from Query/Mutation — a streaming subscription rather than request-response. The resolver stays alive emitting N values while the client remains connected, which is why its `Handler` accepts `func(ctx, emit)`:

```go
resolver.Subscription("orderCreated", func(subscription *gonest.GraphqlSubscription) {
	subscription.Args(orderFilterSchema)
	subscription.Returns(orderEntitySchema)

	subscription.Handler(func(ctx *gonest.GraphqlContext, emit func(any)) {
		args := gonest.MustParse[OrderFilter](ctx.Args(), orderFilterSchema)
		emitter := gonest.MustInject[*gonest.Emitter](resolver)

		for event := range gonest.Subscribe[OrderCreatedEvent](emitter, ctx.Done()) {
			if event.CustomerId == args.CustomerId {
				emit(event)
			}
		}
	})
})
```

`gonest.Subscribe[T](emitter, done)` is the dynamic counterpart to `NewListener`/`Emit` — a channel scoped to `done` that closes automatically when the client disconnects. `orderService.Create(...)` emits events via `emitter.Emit(OrderCreatedEvent{...})` without needing to know which subscription receives them.

### Transport Protocols

Queries, Mutations, and Subscriptions all dispatch through `/graphql`, multiplexed by protocol:

```
POST /graphql                                          -- Simple GraphQL-over-HTTP
GET  /graphql  (Upgrade: websocket)                     -- graphql-transport-ws
GET  /graphql  (Accept: text/event-stream, no token)    -- graphql-sse, Distinct connections mode
PUT  /graphql -> 201 {token}                            -- graphql-sse, Single connection mode: reserve
GET  /graphql  (with token)                             -- graphql-sse, Single connection mode: connect
POST /graphql  (with token + extensions.operationId)     -- graphql-sse, Single connection mode: execute
DELETE /graphql?operationId=X  (with token)              -- graphql-sse, Single connection mode: cancel
```

## Automatic SDL Generation

Generated SDL is derived directly from the exact same `Schema` used for REST:

```go
type UserEntity struct {
	Id        int64     `json:"id"`
	Email     string    `json:"email"`
	CreatedAt time.Time `json:"createdAt"`
}

var userEntitySchema = gonest.NewSchema(func(t *UserEntity, s *gonest.Schema) {
	s.Property(&t.Id).Integer().Required()
	s.Property(&t.Email).Email().Required()
	s.Property(&t.CreatedAt).DateTime().Required()
})
```

Generates:

```graphql
scalar Email
scalar DateTime

type UserEntity {
  id: Int!
  email: Email!
  createdAt: DateTime!
}
```
