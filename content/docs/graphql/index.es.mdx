`GraphqlResolver` es análogo a `Controller` — registrado vía `module.Resolvers(...)`, reutilizando exactamente la misma `Schema`/`Parse[T]`/`MustInject` que el REST. Cero duplicación de lógica de validación o DI entre REST y GraphQL.

Por convención en proyectos GoNest, las variables de referencia de los resolvers terminan con un guion bajo al final (`_`), ej: `UserResolver_`.

```go
package user

import "gonest.dev/gonest"

var UserResolver_ = gonest.NewGraphqlResolver(func(resolver *gonest.GraphqlResolver) {
	userService := gonest.MustInject[UserService](resolver)

	resolver.Query("user", func(query *gonest.GraphqlQuery) {
		query.Args(userIdParamsSchema)   // misma Schema usada en la validación REST
		query.Returns(userEntitySchema)  // misma Schema alimenta el SDL generado

		query.Handler(func(ctx *gonest.GraphqlContext) any {
			args := gonest.MustParse[UserIdParams](ctx.Args(), userIdParamsSchema)
			return userService.Get(args.UserId) // el valor retornado ES la data
		})
	})
})
```

<Callout type="info">
  El `owner` para `MustInject` debe ser el propio `resolver` (u otro Resolver/Controller) — los builders `Query`/`Mutation`/`Subscription` pasados a sus callbacks no tienen capacidad de resolución de DI propia.
</Callout>

## Registrando Resolvers en un Módulo

Para registrar resolvers dentro de un módulo GoNest, utilízalos con `m.Resolvers(...)`:

```go
package user

import "gonest.dev/gonest"

var UserModule_ = gonest.NewModule(func(m *gonest.Module) {
	m.Name("UserModule")
	m.Providers(
		UserServiceProvider_,
	)
	m.Resolvers(
		UserResolver_,
	)
})
```

## Query y Mutation

Ambos comparten exactamente la misma forma de firma — `.Args(schema)`, `.Returns(schema)`, `.Handler(func(ctx *gonest.GraphqlContext) any)`. El valor retornado por el Handler se convierte en la carga útil `data` de la respuesta GraphQL, igual que en NestJS:

```go
resolver.Mutation("createUser", func(mutation *gonest.GraphqlMutation) {
	mutation.Args(userEntitySchema)
	mutation.Returns(userEntitySchema)

	mutation.Handler(func(ctx *gonest.GraphqlContext) any {
		input := gonest.MustParse[UserEntity](ctx.Args(), userEntitySchema)
		userService := gonest.MustInject[UserService](resolver)
		return userService.Create(input)
	})
})
```

`gonest.GraphqlMutation` es un alias de tipo de `gonest.GraphqlQuery` — el tipo raíz GraphQL asignado en el SDL generado (`Query` vs `Mutation`) se determina por el método que lo registró.

Ambos se despachan a través de un único endpoint HTTP fijo, `POST /graphql`, siguiendo el formato estándar GraphQL-over-HTTP (`{query, variables, operationName}` → `{data, errors}`).

## Subscription

Fundamentalmente diferente de Query/Mutation — una suscripción por streaming en lugar de petición-respuesta. El resolver permanece activo emitiendo N valores mientras el cliente siga conectado, por lo que su `Handler` acepta `func(ctx, emit)`:

```go
resolver.Subscription("orderCreated", func(subscription *gonest.GraphqlSubscription) {
	subscription.Args(orderFilterSchema)
	subscription.Returns(orderEntitySchema)

	subscription.Handler(func(ctx *gonest.GraphqlContext, emit func(any)) {
		args := gonest.MustParse[OrderFilter](ctx.Args(), orderFilterSchema)
		emitter := gonest.MustInject[*gonest.Emitter](resolver)

		for event := range gonest.Subscribe[OrderCreatedEvent](emitter, ctx.Done()) {
			if event.CustomerId == args.CustomerId {
				emit(event)
			}
		}
	})
})
```

`gonest.Subscribe[T](emitter, done)` es el equivalente dinámico de `NewListener`/`Emit` — un canal acotado a `done` que se cierra automáticamente cuando el cliente se desconecta.

## Generación Automática de SDL

El SDL generado proviene directamente de la misma `Schema` usada para REST:

```go
type UserEntity struct {
	Id        int64     `json:"id"`
	Email     string    `json:"email"`
	CreatedAt time.Time `json:"createdAt"`
}

var userEntitySchema = gonest.NewSchema(func(t *UserEntity, s *gonest.Schema) {
	s.Property(&t.Id).Integer().Required()
	s.Property(&t.Email).Email().Required()
	s.Property(&t.CreatedAt).DateTime().Required()
})
```

Genera:

```graphql
scalar Email
scalar DateTime

type UserEntity {
  id: Int!
  email: Email!
  createdAt: DateTime!
}
```
