gonest resolves dependencies by **type**, not by name or string token.

## `MustInject[T](owner)`

Resolves exactly one instance of `T`. Panics if zero or more than one match is
found.

- **Pointer types** (`*UserService`) require an exact type match.
- **Interface types** also require an exact match — there is no structural
  fallback. A provider becomes resolvable by an interface `T` only if it was
  explicitly wrapped for `T` via `gonest.ProviderAs[T](ref)`; see
  [Exporting a provider as an interface](/docs/core-concepts/providers#exporting-a-provider-as-an-interface).

```go
userService := gonest.MustInject[*UserService](controller)
```

## `MustInjectAll[T](owner)`

Resolves **every** provider matching `T`. Never panics on 0 or N matches — use
it for plugin/strategy patterns where multiple providers legitimately
implement the same interface.

```go
type Pingable interface {
  Name() string
  Ping(ctx context.Context) error
}

var HealthController_ = gonest.NewController(func(controller *gonest.Controller) {
  controller.Path("/health")
  pingables := gonest.MustInjectAll[Pingable](controller)
  _ = pingables
})
```

<Callout type="info">
  This is the same pattern used for [Health Checks](/docs/health-checks): any
  number of services can implement `Pingable`, and the health controller
  discovers all of them automatically.
</Callout>

## Where `MustInject` can be called

`MustInject`/`MustInjectAll` are legal inside `Provider`, `Controller`
builders — anywhere the framework guarantees Phase 1 (provider resolution) has
already completed. See [Bootstrap](/docs/getting-started/bootstrap).

From a `Provider` owner, `MustInjectAll[T](owner)` resolves differently than
it does from a `Controller`/`Middleware`/`Guard`/`Interceptor`/`Filter`
owner. A `Provider`'s builder fn runs before any instance exists, so instead
of resolving immediately, `MustInjectAll` returns a fixed-length slice right
away — already sized to however many providers in scope match `T` — and each
element is filled in place once its matching provider actually resolves. Only
`gonest.ScopeSingleton` providers can be members of that slice: a
`ScopeTransient` provider that would otherwise match makes
`NewApp`/`MustNewApp` panic. The slice's element order is not guaranteed, and
zero matches still returns an empty slice rather than panicking — the same
contract as the direct-resolver path above.

`Guard` builders are the one exception: they have **no** `MustInject` support,
because a single guard can be attached across multiple controllers/modules —
there's no single "owner" to resolve against.
